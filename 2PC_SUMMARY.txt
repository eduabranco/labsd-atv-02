🎯 PROTOCOLO TWO-PHASE COMMIT (2PC)
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│ FASE 1: PREPARE (Preparação e Votação)                             │
└─────────────────────────────────────────────────────────────────────┘

    Cliente
      │
      │ INSERT INTO usuarios...
      ▼
  Coordenador (Líder)
      │
      │ [PREPARE]──────────┐
      │                    │
      ├────────────────────┼────────────────┐
      ▼                    ▼                ▼
   ┌─────┐             ┌─────┐          ┌─────┐
   │ Nó1 │ VOTE_YES    │ Nó2 │ VOTE_YES │ Nó3 │ VOTE_YES
   └─────┘             └─────┘          └─────┘
      │                    │                │
      └────────────────────┼────────────────┘
                           ▼
                    Coordenador
                  (Coleta Votos)

┌─────────────────────────────────────────────────────────────────────┐
│ DECISÃO: Todos YES → COMMIT | Algum NO → ABORT                     │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ FASE 2: COMMIT ou ABORT (Execução Atômica)                         │
└─────────────────────────────────────────────────────────────────────┘

  Coordenador
      │
      │ [COMMIT] ou [ABORT]
      │
      ├────────────────────┼────────────────┐
      ▼                    ▼                ▼
   ┌─────┐             ┌─────┐          ┌─────┐
   │ Nó1 │ db.commit() │ Nó2 │ db.commit() │ Nó3 │ db.commit()
   └─────┘             └─────┘          └─────┘
   
   ✅ Dados persistidos em TODOS os nós (Atomicidade garantida!)

═══════════════════════════════════════════════════════════════════════
🔒 GARANTIAS ACID IMPLEMENTADAS
═══════════════════════════════════════════════════════════════════════

✅ ATOMICIDADE
   • Transação commitada em TODOS os nós ou NENHUM
   • Rollback automático em caso de falha
   • All-or-Nothing garantido

✅ CONSISTÊNCIA
   • Validação em fase PREPARE
   • Constraints MySQL verificadas antes de commit
   • Integridade referencial mantida

✅ ISOLAMENTO
   • transaction_lock evita race conditions
   • Transações MySQL com isolamento REPEATABLE READ
   • Queries concorrentes não interferem

✅ DURABILIDADE
   • db.commit() persiste em disco
   • Replicação em múltiplos nós
   • Dados sobrevivem a falhas de hardware

═══════════════════════════════════════════════════════════════════════
🆕 NOVAS FUNCIONALIDADES
═══════════════════════════════════════════════════════════════════════

1. handle_prepare(query)
   └─ Valida e prepara query sem commitar
   └─ Armazena em self.pending_transaction
   └─ Retorna VOTE_YES ou VOTE_NO

2. handle_commit()
   └─ Executa db.commit() na transação pendente
   └─ Limpa estado de transação

3. handle_abort()
   └─ Executa db.rollback() revertendo mudanças
   └─ Limpa estado de transação

4. execute_2pc(query)
   └─ Orquestra protocolo 2PC completo
   └─ Gerencia Fase 1 (PREPARE) e Fase 2 (COMMIT/ABORT)
   └─ Coleta votos e toma decisão atômica
